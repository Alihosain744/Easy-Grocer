# Project Title

Easy Grocery

# Description

this web application is used to make easy the management of a grocery shop, including of products, loan, expenses, incomes, users, categories management. the grocer had already a hard notebook for management of customers loan which might led to many problems including of unorganized loan data related to different customers, the hard notebook might lost that causes the grocer to lost each customer loan data, Possible of mistakes during calculating each customer loan, doesn't had a daily, monthly and yearly record for incomes and expenses. that this web application addresses all these problems.
customers can make orders and track order without having to already signed up to application.
according to grocer neeeds this application support three kind of payment methods including of COD (Cash on Delivery), Pay now and Pay later, which for customers who loans from grocer, the payment method is pay later.
since this is a retail shop, it doesn't support enhanced payment methods that are currently a bit available in Afghanistan.

# Features

1. Give order, track order, regardless of already being Signed Up to the web site.
2. Display list of products currently available along with related info such as stock, price, image, and a button to add to cart.
3. Authorization, as a product list can be look different for Admin and normal user, as Admin can't add to cart a product, instead it can upload a new product to the platform, update a product info, delete a product. see list of products, but a normal user can add a product to his cart, then from there he can proceed an order.
4. Sign Up feature both for Admin and normal user, as Signing Up causes to create a normal user by default, then Admin can modify his privilege to Admin. by default there is already an account for Admin at the back end.
5. Users who already have an account can log to their accounts and from there can make order, see their carts, see products, search products, and filter products.
6. Admin can see a report summary including of todays, this month, this year expenses, and incomes. next to that Admin can see each customer loan.
7. As loan related to each customer comes from corresponding customer order remain field, if a customer pay his loan at the future, then admin can update the remain field for that customer and it automatically reflects to loan summary section.
8. CRUD operation available for Admin in different sections including of incomes, expenses, orders, users, categories, products.
9. A search feature available for Admin along with a filter option so Admin can filter orders based on specific customer and order status.
10. Incomes are linked to orders, if there is an income record for an order, at income section, then that order can't be deleted from the orders section
11. Each form that is used inside this application is already validated, to prevent from un real data flowing to back end.
